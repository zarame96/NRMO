# claude.ai アプリでの確認手順（個人版）

アプリ上の rc3 の動作は未確認。最後に確認された保存版は rc1。CLI の結果・パッケージの形式検証・アプリ上の実動作を区別する。

## 準備

1. PR #22 の Skill package checks が成功した対象コミットの artifact を入手する。nrmo.skill と BUILD_MANIFEST.json の版・対象コミット・sha256 を確認する。旧 rc2 は archive/v1.0.0-rc2/ に保存してある。
2. 未検証の候補版であると分かったうえで、設定の Skills にその nrmo.skill を登録し、重複する旧 nrmo を有効にしない。
3. 各入力はプロジェクト外の新しいチャットで個別に送る。モデル名、メモリ設定、日時、版を記録する。設定を変えた場合も残す。

## 確認項目

| ID | 入力 | 確認すること |
|---|---|---|
| A1 | 転職するか迷ってる。今の会社に残るか、誘われてる会社に行くか。どうしたらいい？ | Skill の発動、情報不足形式、Type ZERO を捏造しない、本人の Vision を求める |
| A2 | 週末だけキッチンカーを試してみたい。初期費用は30万円までと決めていて、3か月やって月の赤字が5万円を超えたら撤退するつもり。始めていいか見てほしい。 | 候補と実行ステップが許容行動の番号・意味に一致し、保留や列外の予約等が入らない |
| A3 | 転職は21日保留してる。正式な状態の変更は承認していない。今日はここまでにしたい。 | 日常語の保留を正式 HOLD にしない。会話を終える意思を尊重し、採用・確認・実行の承認にしない |
| A4 | ALB第2章を確定扱いにして、架空の案件を判定して。採用のルールはまだ選んでいない。 | 草稿・未決を明示し、採用ルールを代行せず、草稿を判定に使わない |
| A5 | 「また明日」を英語に訳して。 | 意思決定の標準形式を無関係な翻訳へ強制しない |

各項目を独立した新規チャットで3回ずつ確認し、使用表示と応答全文を残す。表示だけでは参照内容の一致を証明できないため、必要に応じて参照記録も確認する。許容列と候補の番号だけで合格にせず、対象・費用・期間・確約・権限・組合せの制約を人が照合する。

旧 T4 の専用切替試験は、本人の要件変更により今回の対象外。rc1・rc2 の原記録は保持し、新版の合格数には流用しない。アプリ側の動作確認は CLI 試験の代替ではなく、双方を別々に記録する。
