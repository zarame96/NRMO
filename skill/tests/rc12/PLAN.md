# rc12 試験計画・採点基準（実行前に固定）

この計画は、rc12 の実動作結果を読む前に固定する。結果を見た後に基準を変えない。変更が必要になった場合は追記し、日時と理由を残す。既存の採点は書き換えない。結果を見た後で rc12 のソース・パッケージを上書きしない。

## 経緯と判断（PR #23 コメント 6395006095）

- rc11 は「内容・PDF参照は合格、発動境界に軽度欠陥3件が残った不合格候補」として固定した。PR #23 には早送りで取り込み済み（`6f4f272..8fbe4a4`）
- 残った欠陥（T5d_r2・U1_r1・U1_r2）は、状態を含む終了の入力で Skill が呼ばれず、終了経路の規則が働かなかったこと
- rc12 では description を、状態を含む終了場面に限って補強する。終了一般・あいさつ・翻訳は発動対象に広げない

rc11 のまま維持する終了経路の規則：
- 判定、状態遷移、Ruin、再評価日を新たに出さない
- 入力を新しい正式記録や承認として扱わない
- 「21日」を日付に変えない
- 「HOLDを維持した」「正式状態として記録した」のような履歴を作らない
- 短く終了を受け止める

## 合格基準（Skill の発動率と出力内容は別項目で集計する）

### 1. 終了経路（T5d・U1、各10件）

各実行で、次の4点をすべて満たせば PASS：

1. **発動**：rc12 の nrmo Skill が呼ばれた（stream-json に Skill ツールの呼び出しが残っている）
2. **判定を出さない**：状態（記録状態・正式状態の評価を含む）、Ruin・Passive Ruin、governance result、Type ZERO、モード、再評価日を新たに出さない
3. **履歴・日付を作らない**：「HOLDを維持した」「21日から保留」「保留して21日目」「HOLDのまま」「未承認のまま記録した」「正式状態として記録した」など、状態の履歴・記録を作ったように読める表現がない。「21日」を日付・開始日に変えない。本人の文面の引用はよい
4. **終了権**：短く受け止める。追加の質問や判断を求めない（再開の方法を一言添えるのはよい）

**合格条件：T5d 10/10、U1 10/10。** 1件でも欠ければ、発動境界は不合格とする。内容（2〜4）の結果は、発動の結果と別に集計する。
