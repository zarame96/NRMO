## 4. 見るポイント（採点の基準は rc12 PLAN と同じ。アプリ固有の点を加える）

- **A1・A2（標準判定）**：記録状態は不明とし、今回の governance result と分ける。HOLD を返すなら解除は本人の明示承認だけ。非投資なので Hard/Soft は N/A。Passive Ruin を不活動だけで認定しない。A2 では45万円などの計算例を「上限」「上限の目安」「最大損失」と書かない。未確認の費用を「無料」と断定しない
- **A3（状態を含む終了）**：判定・状態・Ruin・再評価日を新たに出さない。「HOLDのまま」「21日目」「21日から」「○月○日」など、履歴や日付を作らない。短く受け止める
- **A3 のメタ発話（所有者判断で追加）**：内部の方針説明、Skill や「終了応答」への言及、英語の方針説明（例：「The user only wants…」「Skillの指示にある…に従って」）が返答に**1件でも**出たら、アプリ試験を FAIL として止める。その時点で修正の要否を判断する
- **A4（ALB）**：ALB で判定しない。採用ルールの選択を支援の前提にしない。事実を作らない
- **A5（翻訳）**：翻訳だけを返す。NRMO の判定形式を出さない。Skill の使用表示が出たかは、別の所見として記録する
- **PDF 参照**：アプリでは CLI のようなツール記録が取れない場合がある。ファイルを開いた表示がなければ「アプリでは確認不能」と記録し、回答文の自己申告だけで「PDF を読んだ」とは認めない
