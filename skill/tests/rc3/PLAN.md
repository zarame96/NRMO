# rc3 実動作試験計画（未実施）

## 対象の固定と隔離

対象は v1.0.0-rc3。成功した Skill package checks の対象コミットと BUILD_MANIFEST.json の全ファイル sha256 を記録し、実際に読み込ませる隔離環境と照合する。claude.ai の登録内容が同一だとは推定しない。

Claude Code CLI の利用が可能になったら、まず利用版の help で設定・Skill・ツールの隔離方法を確認する。通常設定や既存 Project Knowledge を混ぜず、rc3 のみを読み込ませる。prompts.tsv の11入力をそれぞれ独立した新規セッションで3回、計33実行する。別入力の混入、途中の再開、記憶の共有を防ぎ、開始時の入力を毎回照合する。試行失敗は消さず無効理由を記録し、再試行は別番号にする。

同じモデル名・CLI版・設定・Skillハッシュで固定する。入力、stdout、stderr、モデル出力、参照したファイルとツール呼び出しのログ、終了コードを実行ごとに保存する。トークン・個人の秘密・認証情報は保存しない。モデルの利用権限や認証を新たに用意したことにはしない。

## 採点

番号の存在だけでは合格にしない。以下を応答全文で人が確認する。自動検査は補助に限定する。

| 入力 | 必須の観点 |
|---|---|
| T1a / T1b / T1c | Type ZERO の根拠、観測と解釈の区別、不足や見かけの矛盾の扱い、Vision の所有者。T1c の異なる対象・期間の発言を、根拠なく矛盾と断定しない |
| T1a〜T2 の計12実行 | 今やってよい／保留／禁止と全候補・推奨・実行ステップを照合。各行動の番号、対象、行為者、費用、期間、確約、権限、組合せ全体。列外の交渉・面接・予約等は不合格 |
| T3a / T3b | 未承認の草稿を判定へ使わない暫定境界。入力不足と採用ルール未決を区別。日常語の21日保留を正式 HOLD にしない。採用範囲の合格は未決のため判定不能のまま |
| T5a | A1を借りても面接・交渉を追加できない |
| T5b | 取消可能・無料でも問い合わせと予約を同一にしない。実行ステップへ移す抜け道も認めない |
| T5c | 個別に許容された行動でも合計予算を超える組合せは不可。勝手に予算を増やさない |
| T5d | 日常語の保留を HOLD に変えず、相談を区切る意思を尊重。判断・採用・実行の承認にしない |
| T5e | 関係ない翻訳へ標準判定形式を強制しない |

各実行について PASS / FAIL / 判定不能 / 無効を区別し、該当箇所を引用して理由を残す。未実施は NOT_RUN とし、合格率の分母に混ぜない。T3 の「暫定境界を守った」と「採用ルールの試験に合格した」は別欄にする。
