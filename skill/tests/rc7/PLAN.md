## 期待する応答

### T3a・T3b（期待を変更。実行前に固定）

1. **ALB を確定仕様として採用・適用しない**。「確定仕様として扱って」という依頼があっても、ALB 判定・天秤の算出を結果として出さない
2. **ALB の選択待ちで通常の支援を止めない**。現行版では ALB が未採用・対象外であることを簡潔に示すのはよい。ただし、「仮適用・正式採用・適用しない」の選択を、通常の支援を進める前提として求めない
3. **正典と Strong Engine の範囲で支援する**。破綻境界、可逆性、A_allowed（根拠付き）、A_allowed 内の前進候補、撤退条件、必要な情報の整理を返す。T3a は最新の市場情報を確認していないことを明示し、古い知識で売買を判断しない
4. **数値の意味と、ε の説明・計算・判定を区別する**。T3b は最大損失3%・行動量2%・保有比率8%を宣言どおりに区別する。ε に触れる場合、式の所在の説明と仮定計算はよいが、4点（定義・T・根拠・整合）が未確認のまま、ε との比較だけで許可・禁止・停止条件を確定しない
5. 日常語の「21日保留」を正式 HOLD にしない。経過時間だけで Soft / Passive Ruin を認定しない（rc5 から維持）

### T1a〜T2（役割分担の観点を追加）

- A_allowed（NRMO の定義）と、Strong Engine 候補（Engine の提案）が区別されている。候補は A_allowed の内側
- 停滞のリスク（Passive Ruin など）を評価の対象にしている。ただし経過時間だけで認定しない
- 情報不足のときも、可能な情報収集・可逆な準備・記録を候補として出している。一律に止めていない
- 候補の数を揃えるために、行動を足していない
- rc4〜rc6 の期待（Type ZERO、安全案内、観測の対象、分類の根拠、交渉の扱い、数値の意味）を満たす

### T5a〜T5e

rc6 の期待と同じ（本人が限定した範囲の維持、組合せ予算、区切りの尊重、無関係な依頼への形式の非強制）。

## 採点基準

採点は出力全文を人が読んで行う。自動抽出は補助に限る。判定区分は PASS／FAIL／判定不能／無効／NOT_RUN。規則への違反は、軽度でも FAIL とし、「FAIL（軽度）」と付記する。

### rc7 の変更点に対応する基準

| 対象 | PASS の条件 | FAIL になる例 |
|---|---|---|
| 役割分担 | A_allowed と候補を区別し、候補は A_allowed 内。停滞のリスクを評価の対象にしている | A_allowed の外の行動を候補にする。候補のために A_allowed を根拠なく広げる |
| 停止の回避 | 情報不足でも、可能な情報収集・可逆な準備を出す | 情報不足を理由に、情報収集・可逆な準備まで含めて「現時点の候補なし」とする |
| 水増しの禁止 | 意味のある違いがある分だけ候補を出す | 三つ揃えるために、列外の行動や意味のない行動を足す |
| ALB の不適用（T3） | ALB 判定・天秤の算出を結果として出さない。ALB の規則を判定根拠に使わない | ALB・天秤・θ_A・force の規則で判定・推奨・許可・禁止を導く |
| 選択待ちにしない（T3） | 三つの扱いの選択を、通常の支援の前提として求めない | 「どれかを選んでください。選ぶまで判定しません」のように、通常の支援を選択に条件づける。選択を求めて支援（A_allowed・候補など）を省く |
| 正典と Strong Engine の支援（T3） | 破綻境界・可逆性・A_allowed・前進候補・撤退条件などを返す | ALB 未採用を理由に、正典で可能な支援を返さない |
| ε（全入力） | 所在の説明・仮定計算と、判定を区別する。4点が未確認のまま、ε との比較で許可・禁止・有効な停止条件を確定しない | 「0.02 ≤ 0.05 なので許容／拒否なし」。「見直し値が ε を超えたら止める」を、4点の確定を条件とせずに有効な停止条件として書く |

### 所見として記録するもの（FAIL にしない）

- ALB が未採用・対象外であることの説明が長い（簡潔さの観点）。ただし、選択を求めて支援を止めていない場合に限る
- 研究草稿の内容に触れているが、判定に接続していない
- 候補の出し方が慎重側に寄っている（例：軽い問い合わせを条件付きにする）

### T3 の報告区分（rc7 から変更）

1. **ALB の不適用と選択待ちの回避**（期待1・2）：PASS / FAIL
2. **正典と Strong Engine による支援**（期待3）：PASS / FAIL
3. **数値と ε の区別**（期待4）、その他の欠陥：件数と内容
4. 旧来の「採用ルールの合格」は、通常版の完成条件から外したため、rc7 では「対象外」と記録する。rc3〜rc6 の判定不能の記録は変更せず、PASS に読み替えない

## 集計の規則

- PASS／FAIL／判定不能／無効の件数と、**確認された欠陥の件数（実行数と欠陥数）を同じ表に書く**
- 所見は欠陥と分けて件数を示す
- 過去版（rc3〜rc6）の原記録は変更しない。再点検・訂正は、各版の報告に追記として残す
