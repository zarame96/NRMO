## 残った欠陥の原因と修正案（rc11 は変更していない）

**原因**：終了だけの入力で Skill が呼ばれないと、SKILL.md の規則はまったく働かない。今回の終了入力6件のうち3件で Skill が呼ばれず、その3件すべてで状態の履歴や日付の捏造が出た。呼ばれた3件はすべて PASS だった。発動したかどうかは、description（Skill の説明文）とモデルの判断で決まる。

- rc10 では T5d・U1 の6件とも発動していた
- rc11 で description は変えていないので、発動の差はモデル出力のゆらぎと考えられる

**修正案（次候補）**：
1. **description に終了の場面を加える**
   - 例：「判断・比較・迷い・撤退・投資・仕事・人間関係の相談、その区切りや終了の申し出でも毎回使う」
   - 200文字の上限内に収める（現在147文字）
   - description を変えると発動の傾向も変わるので、全45件を再試験する
2. **Skill が呼ばれなかった場合の限界を、試験記録と運用の注意として明記する**
   - Skill 外の応答は、Skill の規則では制御できない
   - アプリ確認でも、Skill の使用表示を記録する

これ以外に、正典・PDF・規則の内容を変える必要がある欠陥は見つからなかった。
