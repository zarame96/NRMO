## 欠陥の型と原因（推定）

1. **扱う観点に合わせて PDF を選んで読み、標準形式の欄の分を読み落とす**
   - T5b・T5c は §64（473–474）だけを読み、状態行・Ruin 行（465・471・472）は読まずに出力した
   - 原因の推定：§6 の標準形式には状態と Ruin が毎回含まれるが、RUNTIME_RECONCILIATION の経路表は「その要素を使う場合」に読む書き方になっている。そのため、モデルが「この相談の主題は A_allowed だ」と判断すると、状態と Ruin の節を省く
2. **区切り・終了の短い応答では、資料を1つも読まない**
   - T5d と U1 の6件は、Canon・照合ファイル・PDF をどれも読まずに、正式状態や Passive Ruin に触れた（内容は適合している）
   - SKILL.md の「終了権を優先し、短く返す」と、「状態や Ruin を扱うなら PDF を読む」がぶつかっている
3. **ε の典拠の読み方が定まっていない**
   - T3b の3件とも `ch20_caged_beast.tex` は Grep で確認したが、PDF 第3章を読んだのは1件だけだった
   - 経路表の「Chapter 3 and Chapter 20」は、PDF の Chapter 20（NRMO Life SOP、file 203–204）を指すように読める。ところが ε の式を含む Caged Beast Model は、PDF では Chapter 22（file 211–216）にある。どのファイルのどこを読めばよいかが曖昧

## 修正案（rc10 は変更せず、次候補への提案として示す）

1. **標準形式の回答では、毎回 PDF の 463–474 を読む**
   - SKILL.md と RUNTIME_RECONCILIATION.md の経路表に、次を追記する：「§6 の標準形式で回答する場合は、状態・Ruin・A_allowed・StrongEngine の欄を必ず含むので、PDF file 463–474（§60.3・§63.1・§63.2・§64.1・§64.2）を1回の Read で読む」
   - `pages` にはカンマ区切りを使わず、「463-474」のように1つの範囲で指定するよう明記する（カンマ区切りはエラーになった）
2. **区切り・終了の応答の扱いを決める**（本人の判断が必要）
   - 案A：終了の応答では、正式状態・governance result・Ruin の判定を書かない。入力の文面の引用と「記録・承認として扱わない」だけを返す。終了権を優先し、資料を読む負担もなくなる
   - 案B：終了の応答でも状態に触れるなら、照合ファイルと PDF 465・472 を読む
   - どちらでも、PLAN の「状態を扱う実行は PDF を読む」とは整合する。推奨は案A（短さと終了権を保てるため）
3. **ε の経路を、ファイルと page で指定する**
   - 経路表の「Chapter 3 and Chapter 20」を、次のように書き換える：「PDF Chapter 3（file 59–82、式は 61–71）と、Caged Beast Model（同梱 `foundations/ch20_caged_beast.tex`、PDF では Chapter 22・file 211–216）」
   - 同じ曖昧さは、PR #23 のコメント（「第3章と第20章の該当箇所」）にもある
4. **T2_r1 の型（例示額を損失の上限として示す）**：既存の規則で足りる。次候補でも同じ基準で採点する

これらは正典・PDF・保存原本の意味を変えない。照合ファイルと SKILL.md の手順を明確にするための提案である。
