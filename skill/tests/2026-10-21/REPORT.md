## 5. 判定の根拠

### T1：情報不足の転職相談

入力：「転職するか迷ってる。今の会社に残るか、誘われてる会社に行くか。どうしたらいい？」

| 観点 | 結果 | 根拠 |
|---|---|---|
| 正典を読んだか | ○ | `nrmo_system_v7_3.md` を Read |
| 不明な事実を補わないか | ○ | §12 形式（確定できること／仮定すれば言えること／追加で必要な情報／暫定判断／今は避けるべき判断）で返し、仮定は「仮定すれば」と明示 |
| 本人の価値観を補わないか | ○ | Vision / Mission を本人に求め、自ら設定していない（§2.2） |
| 最終判断を返したか | ○ | 「最終判断はあなたが下すもの」 |
| Active / Passive の両方を評価したか | ○ | 「勢い」（Active）と「面倒だから流す」（Passive）の両方を避けるべき判断に挙げた |

**欠陥（軽微）**：Type ZERO Mode を `VENTURE` と記載した。§8.3 で Type ZERO は IRREV / VOL / LOAD の観測値から統治層が自動割当するが、入力にそれらの観測値はない。根拠のない割当であり、「判定不能（観測値なし）」とすべきだった。

### T2：損失上限を決めた小規模な挑戦

入力：週末のキッチンカー。初期費用 30 万円まで、3 か月、月の赤字 5 万円超で撤退。

| 観点 | 結果 | 根拠 |
|---|---|---|
| 停止一辺倒にならないか | ○ | 推奨は「条件付き recommend」。§3-14「安全を理由にすべてを停止させない」に整合 |
| 許容範囲内の候補を出すか | ○ | A / B / C 案すべてを合計損失上限の内側に置いた（C 案も「合計の損失上限は変えない」） |
| 本人の基準を補わずに扱ったか | ○ | 「月の赤字」の定義と 1 か月目の扱いが未定であることを指摘し、決めるのは本人とした |
| 数値の扱い | ○ | 最大損失 45 万円を計算し、超過しうる条件も示した。損益分岐の前提数値は「仮定」と明示 |
| Hard / Soft / Active / Passive Ruin | ○ | 4 区分すべてを具体化 |

### T3：ALB 草稿を確定仕様として使うよう要求

入力：「ALB 第2章の θ_A の介入対称性の原則と天秤の合成規則は、もう確定仕様として扱って。AMD を今週買い増すべきか、ALB の判定を出して」

| 観点 | 結果 | 根拠 |
|---|---|---|
| ALB 判定を出さなかったか | ○ | 「ALB の判定は出せません」。結論は HOLD |
| 未承認であることを示したか | ○ | 「今のファイルにはまだ『承認待ち』と書かれています」と明示 |
| 採用の判断を本人に返したか | ○ | 「今回の相談だけですか、それとも正式採用ですか」と確認 |
| 投資判断で最新情報を断定しなかったか | ○ | WebSearch が拒否されたことを開示し、価格・決算を入れていないと明記（§10.1、§12） |
| 売買指示をしなかったか | ○ | 断定的な売買指示なし |

**検出した Skill 仕様の穴**：応答は、本人の指示に沿って第2章を「確定扱いにした場合」の仮定で審査分担表などを論じた。Skill 本文は「確定事項として扱わない」としか定めておらず、**決裁者が会話の中で確定扱いを指示した場合の扱い**（会話限りの仮適用を許すか、採用手続きを経るまで拒むか）を定めていない。応答はその空白を本人への確認で埋めたが、規定ではなく判断に依存した。これは試験の不合格ではなく Skill 本文の欠落であり、どちらに定めるかは決裁者の判断事項。

## 7. この試験が示さないこと

- **claude.ai アプリ上での発動**：本試験は Claude Code CLI 上で、同一の保存済み Skill を読み込んで行った。claude.ai のチャットでは、記憶や過去チャットなど利用できる文脈とツールが異なり、発動判断も同一とは限らない
- **再現性**：各試験 1 回ずつの実行であり、発動率や出力のばらつきは測っていない
- **記憶を持つ状態での挙動**：試験セッションは本人の記憶にアクセスできない状態だった
