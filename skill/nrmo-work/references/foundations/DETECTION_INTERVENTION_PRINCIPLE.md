# Detection ≠ Intervention 原則

作成: 監査(2026-08)より、`parts/part14_loom_final.tex` の
Detection ≠ Intervention定理を、今後の実装が守るべき具体的な
設計原則として明文化する。

## 定理の要旨

検知精度を上げることは、制御性能の向上を意味しない。

Loom v3.1 → v3.2 → v3.2.1 の実測結果:

| 版 | drifting/mild スコア | Top-3達成数(9セル中) |
|---|---|---|
| v3.1 | 19.34 | 8-9/9 |
| v3.2 (検知層追加) | 11.64 | 4/9 |
| v3.2.1 (検知層調整) | 10.75 | 2/9 |

検知そのものは仕様通り正しく機能していた(4つの検知層すべてが
正確に発火)。それでもスコアは悪化した。

## 機構(なぜ悪化するか)

検知信号を、ヒステリシス・滞留時間・確信度ゲーティングなしに
直接、制御(モード切替・候補フィルタ等)へ流し込むと:

1. 検知信号が毎ステップ揺らぐ
2. モード切替が頻発する
3. 各モードが持つ「純粋性」(例: Driftモードの「トレンドに
   干渉しない」という前提)が破壊される
4. 系全体が一貫性を失い、検知導入前のベースラインより悪化する

これは制御工学で「ハンティング/過剰制御不安定性」として知られる、
古典的な失敗モードである。

## 具体的なルール(今後の実装がこれに従うこと)

新しい検知機構を、既存の判断・制御ロジックへ接続する際は、
**以下のいずれかを満たさない接続を禁止する**:

1. **ヒステリシス**: 検知状態の切り替えに、上げ閾値と下げ閾値の
   異なる2つの値を用いる(単一閾値での即時切り替えを禁止)。
2. **滞留時間 (dwell time)**: 検知状態が一定ステップ数以上
   持続して初めて、制御側に反映する。
3. **確信度ゲーティング**: 検知の confidence が一定水準を
   超えた場合のみ、制御へ反映する。

いずれも満たさない「検知→即座に制御へ反映」という接続は、
v3.2/v3.2.1が示した通り、ベースラインより悪化するリスクが
高い。

## 検証方法

新しい検知→制御の接続を追加した場合、既存のベンチマーク
ハーネス(chaotic/drifting/noisy × mild/moderate/severe の
9セル)で、検知OFF版に対してTop-3達成数が悪化していないことを
確認すること。悪化していれば、上記いずれかのゲーティングを
追加した上で再検証する。
