# Phase D Scope Guard

Parent issue: #6  
Phase: D — Mechanical consistency audit

This phase is specification/publication consistency work only.

Allowed changes:
- classify remaining required-keyword occurrences as current, historical/non-normative, implementation evidence, or conflict;
- add Part-level Canon-precedence notices to preserved baseline material;
- fix residual authority/mode/state wording that can still be read as current controlling semantics;
- clarify publication version, source revision, Part baseline lineage, and implementation-version provenance;
- record implementation deltas for Phase E.

Forbidden changes:
- runtime or algorithm changes;
- creating implementation modules to match documentation;
- changing numerical thresholds or empirical results;
- deleting preserved historical material merely to eliminate search hits;
- changing the Normative Canon to accommodate stale prose or current code;
- performing DecisionCompass implementation changes in this phase.

A remaining literal legacy term is acceptable only when its status is unambiguous under the Canon/precedence/provenance rules.
