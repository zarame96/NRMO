# 過度な防御 — NRMO「数値クソ」の根本原因と解決

## 診断 (設計者)
> 原因は過度な防御

これまでの全 domain (store / investment / romance / 文明) で観測された
「数値クソ」「停滞」「破滅」は、すべて **過度な防御** に集約される。
設計者は一貫して「最大前進が正」と指示していたが、実装側がそれを
過度な防御へ歪め続けていた。

---

## 過度な防御を生んだ 4 つの誤り

```
誤り1: engine 配置の取り違え
   StrongEngine Ω Full を civ-sim 側と誤認 → 現実が保守的な civ 最適化に支配された

誤り2: 評価地平が短すぎた
   成長の長期複利を見られず、短期の exposure 増だけ見て防御を最善と誤判定

誤り3: minimum viable (最低限の前進) という解釈
   「最大前進」を「最低限の前進」に矮小化 → 停滞 → passive death

誤り4: 「停滞 = 安全」という誤読
   動かないことを安全とみなし、緩慢な死 (passive ruin) を risk として認識しなかった
```

---

## 実証: 過度な防御が数値を殺していた

```
文明 domain (評価地平の効果):
   horizon 12  → 最善 g=0.10 (防御)     ← 過度な防御に倒れる
   horizon 100 → 最善 g=0.30 (持続成長) ← 正しい最大前進
   差は評価地平だけ。短い地平が過度な防御を生んでいた。

store domain:
   minimum viable (過度な防御) → ruin 100%, surv 46  ← 朽ちた
   最大前進                    → ruin   0%, surv 300 ← 生存

investment domain:
   v6.1 equity 2% (過度な防御) → 死なないが稼がない
   二層構造 (相場適応)         → 下落で勝ち、複利停止を回避

romance domain:
   observe_wait (過度な防御)   → passive_ruin 100%
   二層構造 (能動的 + 倫理)    → passive 0%, active 0%
```

---

## 解決 (NRMO v7)

```
1. 二層構造: 現実 StrongEngine Ω Full (最大前進) + civ-sim MaxForwardEngine (極端探索)
2. 長期評価: domain ごとに適切な評価地平 (文明は長期、store は短期)
3. 最大前進 default: 「最低限」ではなく「最大前進」から始める
4. 停滞排除: 停滞を ruin の一種として候補から外す
5. 縁での方向転換: 破滅の縁 (例: 文明 g=0.55) でのみ前進方向を変える (g=0.30)
```

「破滅しない範囲での最大前進」— これが過度な防御の対極であり、NRMO 本来の姿。

---

## 補遺: 世界依存性 (world-dependence) — 過度な防御が最善の世界もある

設計者の追加洞察: V9 minimum では過度な防御・超慎重姿勢が高得点だった。
つまり「過度な防御」そのものが悪なのではない。

```
正確な診断:
  「過度な防御が悪」ではなく、
  「その世界では最大前進が最善なのに、過度な防御を選んでいた」ことが誤り。

世界ごとに最善は変わる:
  store           → 攻撃が最善 (過度な防御は破滅)
  文明 (長期)      → 持続成長が最善 (極端攻撃も極端防御も劣る)
  V9 minimum の世界 → 超慎重・過度な防御が最善 (こういう世界もある)
```

二層構造の役割は「最大前進の押し付け」ではない。
civ-sim (MaxForwardEngine) が攻撃ピークと防御ピークを両方探索し、
**その世界の真の最善** を発見する。過度な防御が最善の世界なら、
civ-sim はそれを発見し、現実 StrongEngine はその防御を選ぶ。

これが「最大前進 default + 世界ごとの最善探索」の正しい意味。
default は最大前進だが、探索の結果がその世界で防御を指すなら、防御こそが正解。
