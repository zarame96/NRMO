# Phase C Scope Guard

This phase is documentation/provenance repair only.

Allowed changes:
- classify concrete module/file descriptions as historical/reference snapshots;
- identify the current checked-in implementation tree at the audited ref;
- distinguish canonical Norn from historically overloaded implementation names;
- add PDF-visible provenance notices;
- add implementation-evidence priority rules.

Forbidden changes in this phase:
- creating missing implementation modules solely to match old documentation;
- changing runtime behavior;
- renaming implementation classes or files;
- deleting historical code listings;
- rewriting archives;
- changing the Normative Canon to match stale implementation prose;
- DecisionCompass conformance work;
- publication/version-number repair reserved for Phase D.

If a real current implementation mismatch is discovered, record it and defer the implementation change to Phase E or a separate implementation issue.
