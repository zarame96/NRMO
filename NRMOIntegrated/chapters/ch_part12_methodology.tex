\subsection{$\Omega$ Full Engine --- What It Does}
\label{sec:methodology-v50-engine}

\paragraph{$\S 1$ Candidate Population System.}
base (11 templates) $\to$ mutation ($\pm 0.05$, 1--3 variants) $\to$
synthesis (pairwise avg + $\pm 0.03$) $\to$ invention
(state $\times$ world analytical) $\to$ pool (~23--35 candidates).
Pool passes through governance filter before scoring.

\paragraph{$\S 2$--$\S 3$ Mutation \& Synthesis.}
Mutation: local perturbation of each action component. Synthesis:
average of random pairs $+$ noise.

\paragraph{$\S 4$--$\S 5$ Wolf Pursuit Mode.}
Trigger: $E \ge 50$, $G \ge 45$, $O \ge 45$, $K \ge 45$, $X \le 35$,
$\mathrm{d}O \ge 0$, $\mathrm{d}K \ge 0$. Effect: depth $= 8$,
repeats $= 5$, portfolio $= (0.75 / 0.15 / 0.10)$, +6 extra
candidates.

\paragraph{$\S 6$--$\S 7$ Edge Survival Guard.}
Trigger: fragility $> 0.65$, Vulnerable world, $E < 40 + X$ rising,
$G < 40 + O$ falling. Effect: portfolio $= (0.45 / 0.45 / 0.10)$,
RiskAdj reference injected.

\paragraph{$\S 8$ Portfolio Synergy.}
Pairwise compatibility matrix for hedge selection.

\paragraph{$\S 9$ Dual Objective.}
Ruin is \emph{not} in evaluation function (rollout just terminates).
\texttt{survived\_ratio} as multiplicative signal.

\paragraph{Long-Horizon Drift Control (critical fix).}

\begin{lstlisting}[basicstyle=\ttfamily\scriptsize,frame=single]
g_sust = clip(0.15, 0.40,
              0.28 + 0.08*E/100 + 0.06*G/100
              - 0.10*X/100 - 0.05*env_drag)
drift = max(0, g - g_sust)
        * env_sensitivity
        * exposure_factor
        * gov_buffer
final_score = rollout_score - lambda_drift * drift
\end{lstlisting}

\begin{itemize}
\item $\lambda_{\mathrm{drift}} = 1.0$ (default, validated).
\item Normal world: drift $\times 1.25$.
\item Portfolio hedge: prefers $g \le g_{\mathrm{sust}}$ candidates.
\end{itemize}

\subsection{Key Design Decisions and Rationale}
\label{sec:methodology-v50-rationale}

\paragraph{Why $\Omega$ Full underperformed initially.}

\begin{enumerate}
\item \textbf{Portfolio dilution}: Blending every step destroyed the
best candidate's signal. Fix: pass-through when score gap $> 0.05$.
\item \textbf{Growth bias in scoring}: productivity $\propto g$,
weight $= 1.00$ dominated other factors. Fix: sustainable
productivity $= \mathrm{prod} \times \min(E / 55, 1) \times
\min(G / 45, 1)$.
\item \textbf{Candidate rejection}: Too many invented candidates
were vetoed by governance. Fix: over-generate (mutation +
synthesis) so filter still leaves diversity.
\item \textbf{H1000 collapse}: Short rollout (depth 4--8) couldn't
detect cumulative $E$ depletion. Fix: drift estimator as cheap
long-horizon surrogate.
\end{enumerate}

\paragraph{Why governance--execution separation matters.}

\begin{itemize}
\item Passing governance thresholds (\texttt{growth\_cap},
\texttt{exploration\_floor}) to engine $=$ violation.
\item Engine becomes dependent on governance internals $\to$
architectural invariant broken.
\item The 0.55 score required this violation; the 0.50 score does
not.
\item Monograph: ``Engine has no independent legitimacy without
upstream clearance.''
\end{itemize}

\subsection{How This Was Found}
\label{sec:methodology-v25-discovery}

\subsubsection{The Option C detour}

This session started by attempting Option C from
SESSION\_HANDOFF-7: drop v5.2's unmodified \texttt{OmegaFullEngine}
into the new stack via an adapter
(\texttt{engine/omega\_v52\_adapter.py}), to test the hypothesis
that v5.2's PStress 65\% comes from coupled $\Omega$ Full internals
lost in v2.1's piecemeal port.

Three configurations were tested:

\begin{itemize}
\item \textbf{C1}: adapter only, v5.2 $\Omega$ Full unmodified.
\item \textbf{C2}: adapter + post-action correction
($g \to s_f$ shift in fragile worlds).
\item \textbf{C3}: adapter + monkey-patched
\texttt{score\_candidate} with mode-aware penalty.
\end{itemize}

Initial measurements at $n = 20$--30 suggested big wins
(C3 PStress 70\%, FER 70\%). But the next subsection explains why
those numbers were unreliable.

\subsubsection{Concern resolution}

Before drawing conclusions, the user asked for the listed concerns
to be resolved:

\begin{enumerate}
\item \textbf{Monkey-patch effectiveness (\#5)}: $\checkmark$
Verified --- patch is invoked (363 calls per 50-step Vulnerable
episode), produces measurable score deltas (Recovery mode avg
$-0.0446$, max $-0.20$). v5.2's \texttt{OmegaFullEngine} accesses
\texttt{score\_candidate} through module-attribute resolution, not
local capture, so patches apply correctly.
\item \textbf{RNG wrapper equivalence (\#3)}: $\checkmark$
Acceptable --- \texttt{\_RngAdapter} consumes uniforms correctly for
\texttt{random / exponential / choice / uniform} (matches numpy).
\texttt{standard\_normal} uses Box-Muller (2 uniforms) where numpy
uses ziggurat ($\sim 1$ uniform), but distribution is correct.
\item \textbf{Transition equivalence (\#2)}: $\checkmark$
\textbf{Exact match} --- v2.1 and v5.2 transition functions agree to
0.000000 on the deterministic part. Physics is identical.
\end{enumerate}

\subsubsection{The decisive measurement}

After resolving the structural concerns, we re-measured v2.1, C1, C3
at $n = 50$ with identical seeds, identical chunked-run methodology,
all environment variables explicitly set. Results were dramatically
different from previous $n = 20$--30 measurements --- and revealed
that several earlier ``C1 vs C3'' comparisons had been measuring
\textbf{C3 vs C3} because \texttt{OMEGA\_C3=1} was the implicit
default.

True $n = 50$ results (chunked, env-controlled):

\paragraph{Two findings.}

\begin{itemize}
\item C1 (adapter alone) provides \textbf{no benefit} over v2.1 ---
the v5.2 $\Omega$ Full coupling hypothesis from
SESSION\_HANDOFF-7 \S 8 is not supported.
\item C3's FER $+12$ comes from the \textbf{score patch itself},
specifically the \texttt{Recovery} mode penalty
($-0.25 \cdot g$), not from v5.2 internals.
\end{itemize}

\subsubsection{The C3 $\to$ v2.5 transplant}

Source attribution test: disabled the Recovery patch in C3 $\to$
FER dropped back to 48\% ($=$ C1). So the FER gain depends entirely
on the productivity penalty. v2.1 already has mode-aware
productivity weights for BUFFER / RETREAT but \textbf{leaves PROBE
at 1.00}.

In MAPLayer mode distribution, FER spends $\sim 32\%$ of its steps
in PROBE. Adding a PROBE penalty (\texttt{prod\_w = 0.92}) to v2.1
captures the same effect without needing v5.2 adapter, monkey-patch,
or 40\% speed loss.

\paragraph{Result.}
v2.5 $=$ v2.1 + 1 line. FER $50 \to 60$ (close to C3's 62),
Vulnerable $24 \to 26$ (slightly better than v2.1, much better than
C3's 16). Overall best of the three.

\subsection{Honest Limits}
\label{sec:methodology-v25-honest-limits}

\subsubsection{Statistical}

\begin{itemize}
\item $n = 50$ per world, SE $\pm 7$--10 pt. FER's $+10$ pt at
$z = 1.01$ means $p \approx 0.16$ --- a real trend but not
statistically significant at $p < 0.05$.
\item Overall $+2.0$ pt at $z = 0.47$ is within noise. \textbf{v2.5
is ``v2.1 with PROBE penalty''; cannot be claimed as significantly
better overall, only as same-or-better with a meaningful FER
trend.}
\item 500-run confirmation needed before the FER number can be
quoted in publication.
\end{itemize}

\subsubsection{Methodological}

This session caught \textbf{its own measurement errors} during
C1 / C2 / C3 comparisons. The previous SESSION\_HANDOFF-7 also had
measurement errors (the v5.2 65\% PStress baseline was $n = 3$ in
some configs; v2.1's 24\% Vulnerable was 500-run robust but compared
against unstable C3 numbers). The chunked-run methodology with
explicit env vars (\texttt{OMEGA\_BACKEND}, \texttt{OMEGA\_C3},
\texttt{OMEGA\_C2}) and json-checkpointed results is now the
standard going forward.

\subsubsection{Architectural}

\begin{itemize}
\item v2.5 preserves the governance--execution separation that has
held since v2.0.
\item \texttt{governance/nrmo\_core.py} and
\texttt{governance/tuning\_layer.py} untouched.
\item The PROBE penalty reads only \texttt{mode} (passed parameter,
not governance state) and \texttt{action[0]} (g component). No
leak.
\item \texttt{engine/omega\_v52\_adapter.py} remains in the codebase
as a research artifact and toggle (\texttt{OMEGA\_BACKEND=v52}).
It works, but is not the production path.
\end{itemize}

\section{Cross-Session Methodological Principles}
\label{sec:methodology-cross-session}

The two session-handoff documents establish the following recurring
methodological principles:

\begin{enumerate}
\item \textbf{Constitutional compliance is non-negotiable.}
The 0.55 score in v5.0 was abandoned because achieving it required
violating governance--execution separation. The 0.50 score is
correct under constitutional compliance. ``Engine has no independent
legitimacy without upstream clearance.''

\item \textbf{Honest reporting of measurement errors.}
Both sessions explicitly recount their own measurement errors:
v5.0's portfolio dilution discovery; v2.5's discovery that ``C1 vs
C3'' comparisons were measuring C3 vs C3 due to
\texttt{OMEGA\_C3=1} default. This honesty is itself part of the
methodological standard.

\item \textbf{Chunked-run methodology with explicit environment.}
v2.5 standardised the chunked-run pattern with explicit
environment-variable control and JSON checkpointing. This is now
the production standard.

\item \textbf{Architectural-invariant audit at each session.}
Every session reports separation status ($\checkmark$ vs.~$\times$).
v5.0 row ``P6 + action\_risk'' was explicitly marked $\times$
(violated) and the design was reverted.

\item \textbf{Single-line changes preferred over architectural
changes.}
v2.5's entire delta is one line. The session caught itself
attempting a more elaborate adapter-based hypothesis (Option~C) and
reduced it to the minimal change with the same effect.

\item \textbf{Statistical honesty about $n$.}
v2.5 explicitly reports SE $\pm 7$--10 pt and refuses to claim
significance for the FER $+10$ pt trend ($p \approx 0.16$).
500-run validation is on the deferred-priority list.

\item \textbf{Source-of-truth files are frozen.}
Both v5.0 and v2.5 list explicit ``do not change'' files
(\texttt{governance/}, \texttt{core/state.py},
\texttt{core/worlds.py}). Engine changes are confined to
\texttt{engine/} and \texttt{strategies/}.
\end{enumerate}
